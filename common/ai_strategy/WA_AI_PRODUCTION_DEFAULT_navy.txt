# AI convoy production was re-enabled on 2026-08-16 ([convoys]). Since 2024-02-20 (358e8be12,
# commit message "ai", no recorded reason) common/units/equipment/convoys.txt carried
# `can_be_produced = { is_ai = no }`, so every block in this section was dead code and AI
# convoys came from the free-stockpile cheat decisions removed in 8643389d5
# (GER/ENG/USA/SOV/CAN_AI_cant_build_convoys, WA_convoy_fix, *_is_greedy). The likely
# purpose of that lock - the classic vanilla failure is a navy hogging dockyards on convoys -
# is covered here by the stop blocks, by CONVOY_MAX_NAV_FACTORIES_PER_LINE = 15 and by
# NDefines.NAI.MISSING_CONVOYS_BOOST_FACTOR = 0.0 (05_defines.lua; vanilla 50), which keeps
# the engine's "I am short of convoys, divert dockyards" reflex OFF. Three layers now act:
#   - VOLUME: the engine's naval unit_ratio pool. The baseline block below gives every naval
#     producer `unit_ratio convoy = 15`; it was moved out of wa_default.txt so countries
#     excluded from that strategy no longer lose their only explicit convoy ratio.
#   - FLOOR (this section): equipment_production_min_factories values ACCUMULATE across the
#     enabled tiers (>3 dockyards -> 1, >20 -> +3, >40 -> +3, >80 -> +3, war+<100 -> +3),
#     so a line always exists while the stock is low, whatever the pool decides.
#   - BRAKE: the stop blocks (equipment_variant_production_factor -200) once the stock is
#     healthy - previously dead code, so its suppression of a unit_ratio-driven line is
#     itself unverified until a campaign scores checklist R56.
# Stock is read with has_equipment (absolute convoy count - the form the removed decisions
# proved in play), NOT stockpile_ratio, whose meaning for the convoy archetype is undocumented.
# Floor and stop bands are hysteresis pairs whose ON states are mutually exclusive: a floor
# switches on below its low bar and off above its high bar; the stop switches on above the
# floor's high bar and off at/below the floor's low bar. Walk it for a minor: 350 -> stop on;
# falls to 250 -> stop still on, floor cannot enable (needs <200); falls to 190 -> stop off
# (<=200), floor on; rises to 250 -> floor on, stop cannot enable (needs >300); rises to 320
# -> floor off (>=300), stop on. Same walk for majors on 500/750/1000.
# THROUGHPUT (the honest number, AGENTS.md P3(f)): a convoy costs 700 IC (vanilla 70) and a
# WA dockyard yields 5 IC/day (00_buildings.txt, vanilla 2.5), i.e. 140 dockyard-days per
# convoy. Floors alone give: 1 dockyard = 2.6/yr, 4 = 10/yr, 7 = 18/yr, 10 = 26/yr,
# 13 (max, with the emergency tier) = 34/yr. The removed cheats granted ENG 1200/yr, USA
# 1800/yr, SOV 280/yr, GER 146/yr, CAN 36/yr. So the floors keep a line OPEN; they do not
# replace the cheat volume - that has to come from the unit_ratio pool (18% of dockyards at
# 15/85 -> ~47/yr for a 100-dockyard navy). The original convoy relief leg was REMOVED by
# [lend-lease-relief] (2026-08-16): that relief system is an overland transfer by ruling. The new convoy
# path is a separate maritime branch and never enters the land A*. Its old donor bar (>1999
# free) was unreachable for every tag. Campaign a232d96c (R56): ENG
# opened 4 lines / 50-57 dockyards for 43 months and was STILL short (tooltip 1944.6: 676
# held / 676 used, trade 49 of 387) - the levers are convoy build_cost_ic and a unit_ratio
# convoy for the 12 majors, NOT bigger own-stock floors (need-blind floors hog dockyards).
# Campaign 2f8cbd51 confirmed the gap: 1943.1 ENG had 0 free convoys, 101 controlled dockyards
# and no line while USA had 1507 free, 122 dockyards and no line. The arsenal boost adds +85
# ratio and a 15-dockyard floor only for an 81+ dockyard major while an eligible partner is
# below that partner's dynamic reserve. The major stop excludes this state in enable AND abort.

#
# Owner ruling: "if there is nothing to build, the countries in RAJ's situation should build convoys
# by default". One type does exactly that and nothing else:
# `equipment_production_surplus_management` decides what the AI builds "when all their needs are
# already met (and it therefore doesn't need/want anymore)" - the install's own wording, in
# common/ai_strategy/_documentation.md. Weighed against the other surplus types, so 100 makes
# convoys the answer for a dockyard with no other claim on it, and takes nothing from a claim that
# does exist.
#
# WHAT THIS BLOCK IS **NOT** THE FIX FOR, and the correction matters because the first version of
# this fix got it wrong. The 36 idle dockyard levels across the five dominions at 1941.6 are NOT
# caused by the convoy ladder above: every minor on the GENERIC naval tech tree faces the same
# ladder and saturates its yards anyway (SWE 17 factories / 16 levels, TUR 21/20, ARG 6/5, BRA 6/5),
# while every dominion on the BRITISH tree runs exactly one (RAJ 1/8, AST 1/6, CAN 1/16, NZL 1/7,
# SAF 1/4). The cause is that they had no ship DESIGN matching their hulls - [commonwealth-handoff],
# common/ai_equipment/ENG_naval.txt. This block is the genuine-surplus case only.
#
# The first version also carried `equipment_production_min_factories id = convoy value = 3/6`.
# REMOVED with [commonwealth-handoff] that type FORCES factories onto the category, and once the dominions have
# escort designs it would have spent their yards on convoys instead of the escorts WA already asks
# them for (`role_ratio naval_escort 50`). A forced floor is the wrong tool for "when there is
# nothing else".
