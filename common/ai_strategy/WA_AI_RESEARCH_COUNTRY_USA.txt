# [equipment-selection] (2026-08-13, checklist R35): suppress the T20/T23 branch so the USA builds Shermans.
#
# WHY THIS IS THE RESEARCH LAYER AND NOT A PRODUCTION ONE
# ------------------------------------------------------
# Campaign 02bd4445 converged the USA `land_medium_tank` role on T23 - six lines, 439
# factories at 1946.1 - and never built a single Sherman, and it did so with BOTH of the
# other candidate levers already shipped and live:
#   * `ai_equipment` priority ([equipment-selection]) is the DESIGN layer; it does not decide what a
#     production line makes.
#   * `production_upgrade_desire_offset` ([equipment-selection]) offsets the desire to UPGRADE an existing
#     line, gating on the stockpile surplus that upgrade waits for - vanilla's own comment
#     at common/ai_strategy/SOV.txt:360 reads "100 essentially means we don't require a
#     stockpile surplus". A `+100` on an older wanted chassis is therefore a no-op (you never
#     upgrade *to* an older type), and the type never sees line CREATION - which is the actual
#     failure here, since the USA jumps M3 Lee -> T20 and later opens *new* T23 lines.
# So the only lever that reaches this behaviour is not building the branch at all. This is
# also Expert AI 5.0's primary method.
#
# WHY THIS STRANDS NOTHING - the check that has to be done before any research suppression
# ------------------------------------------------------------------------------------
# `usa_medium_tank_chassis_5` (T23) leads to `usa_modern_tank_chassis_1` (M26 Pershing), and
# the whole USA heavy line (chassis 2-7) hangs off that in turn - 15 equipment tokens. Cutting
# a tech that is the sole path to them would trade a medium-tank preference for the loss of
# every USA heavy and modern tank.
# It is NOT the sole path: `usa_modern_tank_chassis_1` is also reachable from
# `usa_medium_tank_chassis_3_3` (M4A3E8), i.e. from the Sherman branch we are steering onto.
# The technology graph genuinely forks and both prongs rejoin at the modern line.
#
# Known cost, accepted: pre-fix the USA reached the modern line through T23 (researched
# 1943.5.25); it now reaches it through M4A3E8 (1944.2.7 in that campaign), so US modern
# tanks arrive later. The `research_weight_factor` boost below exists to keep that now-sole
# path prioritised.


# FIX 69 (2026-08-14, checklist R40/R35) - THE SUPPRESSION HALF OF FIX 57 IS GONE FROM HERE.
# ==========================================================================================
# `research_weight_factor = -100` on `usa_medium_tank_chassis_4`/`_5` used to live in this
# file. It did not work, and the failure is a property of the LEVER, not of the value:
# campaign f9321934 researched T20 on 1942.9.17 and T23 on 1943.12.26 and then ran six-to-
# seven concurrent T23 lines at ~440 factories to the end of the campaign, never building a
# single Sherman in 127 monthly saves.
#
# Why re-tuning the value would have been a wasted campaign. The token factors the
# technology's `ai_will_do` score (vanilla `_documentation.md:603`). Every WA technology's
# `ai_will_do` is written as `factor = 1` plus `factor = 0` gates, so at any moment most of
# the AI's menu already scores zero - and `0 x anything` is still zero. Down-weighting can
# only reorder a menu that has something positive left on it. The dates say that is exactly
# the state the AI was in: the USA took T20 in the very month it carried
# `WA_AI_unused_research_slots` (set 1942.9.1) and T23 in the very month it carried it again
# (set 1943.12.1). Vanilla's own strongest suppression is `-500` (HUN `air_torpedoe_1`), but
# under the documented formula `-100` already reaches zero and `-500` only clamps there.
#
# The replacement is a HARD gate on the technologies themselves - `allow = { NOT = { is_ai =
# yes } }` in `common/technologies/armor_usa.txt` - which is the construct vanilla uses for
# the same job (`jungle_warfare` in vanilla `common/technologies/infantry.txt` carries
# `allow = { always = no }`, "only from focus!!!"). It gates on `is_ai` alone, so it needs no
# country tag and leaves human players free to research T20/T23 normally. Placing it in a
# technology file is safe despite that folder being tool-managed: the replacer locates and
# rewrites only the `ai_will_do` block (`tools/migrations/ai_will_do/ai_replacer_base/block_finder.py:61-101`), so
# an `allow` sibling survives regeneration - which removes the reason [equipment-selection] avoided this
# folder in the first place.
#
# STRANDING, re-verified from the graph rather than inherited from [equipment-selection]'s comment:
# `usa_modern_tank_chassis_1` has TWO incoming `leads_to_tech` edges -
# `usa_medium_tank_chassis_3_3` (M4A3E8) and `usa_medium_tank_chassis_5` (T23). Gating T23
# leaves the M4A3E8 prong, and the USA researched M4A3E8 on 1944.1.17 in f9321934, so the
# route is live and not theoretical. The boost below is what keeps it prioritised and MUST
# NOT be removed independently of the gate.


# purpose: keep the Sherman branch prioritised, because it is now the ONLY route to
#          usa_modern_tank_chassis_1 and from there to the entire USA heavy line
# range:   +100
# policy:  Country layer; pairs with the [equipment-selection] `allow` gate on usa_medium_tank_chassis_4/_5 in
#          common/technologies/armor_usa.txt and must not be removed without it
# always-on: same reasoning - this is the mod's chosen medium-tank line for the USA in every setup.
WA_AI_RESEARCH_COUNTRY_USA_prefer_sherman_line = {

	allowed = {
		original_tag = USA
	}
	enable = {
		always = yes
	}
	# Permanently on by design, so there is nothing to abort on. Stated explicitly because
	# the engine warns on a strategy with no abort condition at all (ai_strategy.cpp:6907).
	abort = {
		always = no
	}

	# M4A3E8 - enables tank_usa_medium_chassis_4_2 and leads to usa_modern_tank_chassis_1
	ai_strategy = {
		type = research_weight_factor
		id = usa_medium_tank_chassis_3_3
		value = 100
	}
}
