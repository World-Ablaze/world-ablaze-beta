# NOTE (audit 2026-08-11): WA_AI_resource_<r>_shortage_months is only written for
# rubber, steel and aluminium (WA_AI_CONSTRUCTION_PRIORITY_strategies.txt). The
# shortage-months leg of the other reactive triggers below reads a variable that
# is never written (always 0 = false); those triggers work through WA_AI_needs_<r>
# alone (written monthly by WA_AI_misc_effects.txt).

# Check if AI has any shortage of a resource (OR: critical need OR 3+ months history)
# Coal is strategic (every synthetic refinery burns it): prospect PROACTIVELY
# while the effective balance is under +100, not only once it is negative.
# resource@coal is net-available minus unmet demand (see wa-savegame-analysis).
# What resource@coal measures: extraction X, minus the trade law's export share
# (already gone, not counted here), minus own consumption. The engine trade AI
# only imports when that number is NEGATIVE, to bring it back to ~0 - it never
# builds a reserve. So "< 100" is a genuine proactive bar: it fires for a
# producer whose retained surplus is under 100 (and for an importer parked at
# ~0), and stops for a producer keeping 100+ after export share and use. GER
# late 1943 (+15 000) is far above it. See the lessons log entry "resource@X
# and the engine trade AI" before changing the threshold.
# The gauge (resource@) carries the peacetime/proactive case; the WA_AI_needs
# counter (0..3, monthly ramp) carries the wartime shortage case.
# Since 2026-08-15 the prospecting ai_will_do blocks have base weight 0 and this
# trigger is the only thing that gives the coal decisions any weight for ROOT's
# own sake, so a country sitting on +15 000 coal (GER, late 1943) no longer
# re-prospects its states just because civs and PP are free.
# Recorded with Fix 100 (2026-08-17), found while diagnosing the cooperative leg,
# deliberately NOT changed here: (a) the third leg below is DEAD for coal -
# WA_AI_resource_coal_shortage_months has no writer anywhere in the repo and is absent
# from every save of campaign 7c7803a8, so this trigger has two live legs, not three;
# (b) a COUNTRY FLAG named WA_AI_allies_need_coal is set at WA_AI_misc_effects.txt:646
# on a looser bar (an ally under -20) and is read nowhere - the scripted trigger of the
# same name below shadows it in every trigger context. Both are pre-existing.
WA_AI_should_prospect_resource_coal = {
	OR = {
		check_variable = { resource@coal < 100 }
		check_variable = { WA_AI_needs_coal > 1 }
		check_variable = { WA_AI_resource_coal_shortage_months > 0 }
	}
}

		# (always 0) - this trigger works through WA_AI_needs_oil alone.

# Cooperative Layer: Check if allies have critical resource shortages
###############################################################################
# SIBLING STATUS - MEASURED 2026-08-17, Fix 101 (supersedes the Fix 100 note below).
# Fix 100 recorded these eight as structurally identical but UNMEASURED and instructed:
# "Do not convert any of them without a measured ledger; do not assume Fix 100
# transfers", and for the engine-traded six "the import arm may be a legitimate
# faction-scarcity signal, because the ore comes from OUTSIDE the faction rather than
# from ROOT itself. UNTESTED." The ledger now exists (campaign 7c7803a8) and it does
# not support that reservation: 12 (country, resource) pairs fired prospecting 2-10
# times while ROOT's OWN effective balance for that resource was POSITIVE and its own
# WA_AI_needs_<r> read 0 or 1. Strongest, positive at BOTH sampled dates so not a
# snapshot artefact - USA bauxite +2600 / +2703 (7 fires at 12-16 civs each),
# HUN bauxite +2089 (ran to its 10-fire state-flag cap at 6 civs, its ally GER reading
# needs_bauxite = 3), SOV iron +3154 / +2782, JAP bauxite +1089 / +554,
# SAF chromium +634 / +613, ITA bauxite +728 / +1180, SOV chromium +182 / +459,
# JAP oil +113 / +213. So all eight are gated below.
# SHAPE BY PARITY, NO MEASURED HARM CASE: steel and rubber. The other six each have at
# least one. They are gated on the same shape because the structure is identical and a
# divergent sibling is the failure the "open the sibling in the same pass" rule names -
# but a future reader deciding whether the gate earns its keep should know the two were
# carried by parity, not by evidence.
# CONTROLS that make "needs 0/1" mean the reactive leg was genuinely off:
# WA_AI_resource_<r>_shortage_months has a writer ONLY for aluminium / rubber / steel,
# so for iron, bauxite, chromium, tungsten and oil the reactive leg is definitively off
# at needs 0/1. POR tungsten and VIC rubber were EXCLUDED from the harm set - both were
# in no faction at either date, so their cooperative leg cannot fire at all and their
# positive-balance fires are explained by shortage_months instead.
# NOT THIS DEFECT, recorded so the next reader does not re-diagnose it: GER fired the
# Carinthia bauxite decision 10 times at +3346 effective, but with its OWN
# wa_ai_needs_bauxite = 3 at both dates. That counter is held by the WRITER's import arm
# (resource_imported@bauxite > 25, WA_AI_misc_effects.txt:586) while GER's bauxite
# arrives as subject transfer - so it is the REACTIVE leg reading the Fix 100
# dependency/shortage conflation in the writer, not the cooperative leg. Fixing it means
# touching the writer, which changes every reader for every country; out of scope here.

# Fix 101 (2026-08-17): ROOT-side surplus bar on the other eight cooperative legs.
# WHAT IT PROTECTS: the prospecting civilian-factory slots (2-16 per decision) of a
# country that already holds a positive retained balance of the resource.
# THE ENGINE FACT IT ASSUMES: the trade AI acts only on a NEGATIVE balance, importing
# just enough to bring it back to ~0, and never stockpiles. So a positive resource@<r>
# is a real retained surplus and EXTRACTION IS NOT THE BINDING CONSTRAINT - the same
# reasoning as Fix 100, and deliberately NOT "the ally can buy from that surplus":
# resource@<r> is measured after the trade law's export share has already been taken,
# so the retained balance and the exportable share are two different pools (GER coal
# to_export 6928-7419 against exported 100-3167).
# THE TWO BRANCHES: an importer sits ON this boundary, and that is fine - an importer is
# already carried by the reactive leg's own import arm (resource_imported@<r> > 10..40),
# so the flicker costs it nothing. A producer is the branch this gate is for.
# WHY ZERO IS NOT A TUNABLE NUMBER: it is the sign boundary, and no absolute bar is
# derivable from the data - the measured harm spans +6 to +3154 while the resources
# themselves live on incomparable scales (chromium never exceeds ~+650 in the campaign,
# rubber reaches +2841). Eight invented ceilings would be the magic-threshold failure.
# Do not retune it; if it ever needs to move, that is evidence the engine fact above
# changed, not that the number was wrong.
# WHAT SURVIVES THE GATE - the cooperative layer is NARROWED, not deleted. It stays live
# for a ROOT whose own balance sits in the band between zero and the writer's own
# deficit arm, and which is not yet importing: (-10, 0) for aluminium and rubber,
# (-15, 0) for steel, tungsten and chromium, (-25, 0) for bauxite and iron, (-40, 0) for
# oil. Inside that band ROOT is short but has not yet ratcheted needs_<r> above 1, so
# the cooperative modifier is the only weight - which is the layer's distinct function.
# THE COST INSIDE THE RAMP (AGENTS.md (f), at the real cadences - the writer runs on a
# ~2-day event, ai_will_do is evaluated continuously, the counter moves +/-1 per run):
#   t0  a real shortage opens but imports still cover it -> balance >= 0, needs 0.
#       This gate blocks the cooperative leg. The reactive leg is also off. Weight 0.
#   t1  balance goes negative past the writer's arm, needs 1. Gate now OPEN (balance
#       < 0); reactive still off (needs > 1 required). Cooperative leg carries it.
#   t2  ~4 days after t1, needs 2 -> reactive leg on, weight granted regardless.
# So the only window this gate closes that was previously open is t0 - a country with a
# NON-NEGATIVE balance. That is the harm case by definition, and nothing is lost in it.
# HOW TO TELL THE FACT IS GONE: an ally's `imported` line for the resource that RISES
# when a surplus-holding country prospects it.
# NOT THE SAME QUANTITY AS COAL'S BAR. @WA_AI_COAL_COOP_CEILING below is 500 - a CEILING
# placed above coal's proactive reactive bar (resource@coal < 100), because without it
# coal's cooperative layer would be a strict subset of its reactive layer and collapse.
# These eight have no proactive bar, so their boundary is the sign, not a ceiling. The
# two numbers are not comparable and must not be harmonised.
@WA_AI_COOP_ROOT_SURPLUS_BAR = 0

# Fix 100 (2026-08-17): ROOT-side ceiling on the cooperative coal leg.
# WHAT IT PROTECTS: the 5-civilian-factory prospecting slots of a coal PRODUCER.
# Without it this leg is permanently true for any faction leader. An ally reaches
# WA_AI_needs_coal = 3 on EITHER resource@coal < -40 OR resource_imported@coal > 40
# (WA_AI_check_resource_needs, WA_AI_misc_effects.txt), and the import arm is the
# HEALTHY state of an importer, not a shortage. Measured on campaign 7c7803a8 at
# 1943.6: ITA imported 1600 / effective -30, HUN 200 / +11, ROM 400 / +24,
# BUL 267 / +133, FIN 100 / +2 - 11 of 12 sampled cells held by the import arm alone,
# while GER ran coal_prospecting 70 times (11 states, 5 concurrent) on an effective
# balance that climbed 8167 -> 19248 and never came near any own-need threshold.
# THE ENGINE FACT IT ASSUMES: the trade AI imports only to bring a NEGATIVE balance
# back to ~0 and never builds a reserve, so a large positive resource@coal is a real
# retained surplus and extraction cannot be the binding constraint. A producer that
# already fails to ship what it offers (GER to_export 6928-7419 against exported
# 100-3167) is delivery-limited, not mine-limited.
# HOW TO TELL THE FACT IS GONE: an allied coal import line that RISES when a country
# above this ceiling prospects, or an engine build whose trade AI stockpiles a reserve.
# MUST STAY ABOVE the 100 of WA_AI_should_prospect_resource_coal above. At or below it
# this leg becomes a strict subset of the reactive leg and the cooperative layer
# collapses to nothing. Read by this file only, so a file-scoped @ is legal here.
# CROSS-REFERENCE (Fix 101): the other eight cooperative legs use
# @WA_AI_COOP_ROOT_SURPLUS_BAR = 0 above, which is a SIGN BOUNDARY, not a ceiling. The
# difference is not drift: coal alone carries a proactive reactive bar (< 100) that a
# zero boundary would swallow. Do not harmonise the two values.
@WA_AI_COAL_COOP_CEILING = 500

# ALSO CONSIDERED AND REJECTED: additionally requiring the ally itself to be in
# deficit (resource@coal < -40 inside the loop). The wa-lessons-reviewer showed this
# would DELETE the leg rather than narrow it - importing is the coping act, it pushes
# the ally's balance back toward 0, so a genuinely dependent ally never shows a deficit
# while trade works (ITA: -30 on 1600 imported). Same unreachable-gate shape as the
# reverted resource@bauxite > 32 gate.
# COMPETING PROPOSAL, considered and not taken (AGENTS.md (g)): fix the WRITER's import
# arm instead. Objection to this fix: it leaves the conflation live for the reactive
# trigger and the eight siblings above. Mine covers this case because the import arm is
# CORRECT for the importer's OWN decisions - ITA importing 2000 coal should mine and
# refine, and the construction/scoring readers of WA_AI_needs_coal rely on that - and is
# wrong only when a THIRD party reads it as faction-wide scarcity. The defect is in that
# reading, so the fix belongs at this consumer; moving the writer would change every
# reader for every country on the evidence of one.

# Check if any faction ally has critical shortage of resource
# Scope: country. All three call sites are ai_will_do blocks in
# common/decisions/_resource_prospecting.txt (coal_prospecting,
# develop_gulf_province_coal_mines, develop_Ukrainian_coal_mines), where the evaluated
# scope is the country - so the bare check_variable below reads ROOT, exactly as
# WA_AI_should_prospect_resource_coal does. Keep it OUTSIDE any_other_country.
WA_AI_allies_need_coal = {
	check_variable = { resource@coal < @WA_AI_COAL_COOP_CEILING }
	any_other_country = {
		is_in_faction_with = ROOT
		check_variable = { WA_AI_needs_coal = 3 }
	}
}

# Proactive Layer: Check if AI is a strategic exporter
###############################################################################

# Strategic exporters maintain high production during peace.
# WHO is an exporter lives in WA_AI_CONFIG.txt (WA_AI_CONFIG_is_strategic_<r>_exporter);
# this file only adds the capability conditions (peace + a trade posture that
# actually sells). Read by the "Proactive: Strategic exporter boost" modifier
# that tools/needs_aware_generator.py emits into every tungsten / rubber / oil
# prospecting decision (add = 100 on a base of 0).

WA_AI_is_strategic_tungsten_exporter = {
	has_war = no
	WA_AI_CONFIG_is_strategic_tungsten_exporter = yes
	OR = {
		has_idea = free_trade
		has_completed_focus = POR_extraction_industries  # POR focus requirement
	}
}

WA_AI_is_strategic_rubber_exporter = {
	has_war = no
	WA_AI_CONFIG_is_strategic_rubber_exporter = yes
	has_idea = free_trade
}

WA_AI_is_strategic_oil_exporter = {
	has_war = no
	WA_AI_CONFIG_is_strategic_oil_exporter = yes
	has_idea = free_trade
}

# Generic dynamic exporter: any country with Free Trade law and surplus factories
WA_AI_is_dynamic_exporter = {
	has_war = no
	has_idea = free_trade
	num_of_civilian_factories > 50
}
