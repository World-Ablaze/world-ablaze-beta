# [sf-doctrine] The six special-forces branches, ported one-for-one from the legacy technology tree
# that used to live in common/technologies/special_forces_doctrine.txt.
#
# Legacy shape: three XOR roots (mountaineers / marines / paratroopers), each forking twice more.
# The 1.19 doctrine format has one choice per track and then automatic rewards, so each legacy
# root+fork pair became one subdoctrine and the rest of that path became its reward chain. The
# cross-combinations the legacy tree allowed (ski + combat_2, say) are gone; every legacy EFFECT is
# preserved, and the pairing follows the legacy left/right layout.
#
# TWO rewards per subdoctrine, never more: the track window is sized by @doctrine_track_height in
# interface/doctrines/doctrines_view.gui, and WA's land/naval/air subdoctrines all carry two. A
# third reward here renders below the frame. Add effects to an existing reward instead.
#
# Two subunits are granted here and nowhere else - rangers_recon_company_divisional (both
# mountaineers branches) and airborne_light_armour_battalion_divisional (both paratrooper
# branches). If these activation effects are removed, those subunits become unbuildable.
#
# `available` gates on the per-tree unlock techs via WA_SF_DOCTRINE_has_*_tech; the legacy
# `can_unlock_new_special_forces_tree = yes` term is dropped because the XP cost and the
# special_forces_second track now carry that role.
#
# xp_type follows the branch's domain - mountaineers army, marines navy, paratroopers air - like
# the other WA doctrine folders and like vanilla, NOT the legacy tree's army-for-everything. Set
# them all back to army and the six branches compete with the land doctrines for one XP pool.
