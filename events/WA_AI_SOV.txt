# Fix 70 (2026-08-14, checklist R31): force the long-range La-5FN into existence.
#
# THE PROBLEM THIS SOLVES IS "NEVER CREATED", NOT "CREATED AND NOT SELECTED".
# Fix 47 added `fighter_mr_7_lr` to common/ai_equipment/SOV_planes.txt - the La-5FN retuned to
# 1017 km with `internal_slot_1 = fuel_tanks_medium` and the bomb rack removed - and gated it
# behind the WA_AI_EQUIPMENT_needs_long_range_air latch. Three campaigns later
# (bec4d829, 02bd4445, f9321934) the design has never once been instantiated. On f9321934 the
# final save's `equipments={}` registry holds 7 535 entries, 178 of them designed variants,
# and among them EXACTLY ONE `SOV_la_5fn_airframe` design - the stock short-range one carrying
# `self_sealing_fuel_tanks_small` - with zero variants named "long range" anywhere. Meanwhile
# the latch itself was wide open the whole time (`wa_tlm_r47_lrange_n = 72`, first 1939.10,
# last 1946.8), and 17 other registry entries do carry `fuel_tanks_medium`, so neither the
# gate nor the module is the obstacle.
#
# The obstacle is that the engine does not create a second design on an archetype it already
# holds a design for - both La-5FN designs share `SOV_la_5fn_airframe` - so `fighter_mr_7_lr`
# could never be reached by any amount of priority tuning in front of it. Expert AI 5.0 gates
# its groups on `has_design_based_on` precisely to exploit that behaviour.
#
# So this creates the variant explicitly, via a scripted `create_equipment_variant` rather
# than through the `ai_equipment` designer. `fighter_mr_7_lr`'s `target_variant`
# (match_value 1000) then MATCHES an existing design instead of having to create one, and its
# Fix 47 priority ladder finally has something to select. The modules below are copied
# verbatim from that `target_variant` block; if one is ever changed, change both or the match
# breaks silently.
#
# --------------------------------------------------------------------------------------------
# Fix 79 (2026-08-14, checklist R31): PUT THE TECH GATE BACK. Fix 70 as shipped fired on day ~1
# with `allow_without_tech = yes`, and that token does not only waive the tech for the CREATION
# - the resulting design is producible. Campaign `be18f9c7` (build d683fb022, 126 saves)
# measured the consequence: registry id 3207 "Lavochkin La-5FN (long range)" is on the SOV
# multirole line CONTINUOUSLY from 1936.2 to 1944.2 - 96 months, 1-2 lines, 10 to 93 factories -
# while `sov_fighter_multirole_ad_tech_7`, the tech that unlocks `SOV_la_5fn_airframe`, is only
# researched 1943.6.9. The whole Soviet pre-war, Winter War and Barbarossa multirole force was a
# 1943 airframe. The short-range La-5FN the engine designed at tech time (id 7405) never got a
# single factory. R31 "passed" on that campaign for the wrong reason.
#
# The gate is now `has_tech = sov_fighter_multirole_ad_tech_7` - the tech that carries
# `enable_equipments = { SOV_la_5fn_airframe }` (common/technologies/air_techs_sov.txt) and also
# unlocks two of the modules below, `SOV_engine_shvetsov_m_82fn_1x` and `armoured_glass_light`.
# With that tech in, `allow_without_tech` waives nothing and is REMOVED: leaving a no-op token
# that re-opens a campaign-scale hole the moment someone loosens the trigger is a trap, not a
# hedge.
#
# WHY THE "CANNOT LOSE THE RACE" ARGUMENT FOR DAY-1 CREATION IS NOT NEEDED - THE SAME CAMPAIGN
# DISPROVES IT. Fix 70 created the design early because the engine "does not create a second
# design on an archetype it already holds one for". `be18f9c7`'s registry holds BOTH ids 3207
# and 7405 on `SOV_la_5fn_airframe`, and 7405 (short-range, `self_sealing_fuel_tanks_small`) is
# the LATER id - i.e. the AI designer created its own design on that archetype years after this
# event had already put one there. A pre-existing design on the archetype therefore does not
# block a later creation, in either direction, so creating this variant at tech time is safe.
# The archetype-uniqueness rule, whatever its exact shape, is about which design an
# `ai_equipment` GROUP will instantiate - not a veto on `create_equipment_variant`, which is an
# unconditional effect.
#
# The event still fires from its own `trigger` + `mean_time_to_happen`, i.e. strictly AFTER the
# tech completes, never in the same instant. That keeps Fix 70's second reason for not using
# `on_research_complete` (which fires for human players too; this event is `is_ai`-gated, so a
# SOV player's design list is untouched) while removing the first, which no longer applies.
# Note the LaGG-3 `on_research_complete` site at common/technologies/air_techs_sov.txt:1589
# currently FAILS at runtime - `logs/error.log` carries `equipment_effects.cpp:814 ...
# 'Lavochkin LaGG-3-35' - Equipment category differs from that of the type` - a separate live
# defect this fix does not inherit, but the exact error class to watch for on a boot test here.
# --------------------------------------------------------------------------------------------
#
# `mark_older_equipment_obsolete` is deliberately left at its default of `no`: the stock
# short-range La-5FN (`fighter_mr_7`) is the intended design whenever the range latch is shut,
# and obsoleting it would remove the mod's own off-gate default. (It would also achieve
# nothing on its own - `obsolete=yes` does not gate AI production; see wa-lessons-learned.)
############################################################################################################
country_event = {
	id = sov_armor.980
	hidden = yes

	mean_time_to_happen = { days = 1 }

	fire_only_once = yes

	# Fix 79: BOTH techs below are required, because nothing here waives a module
	# tech - `allow_without_tech` never did, and it is gone now.
	#
	# SCOPE OF THIS GATE, stated honestly: it covers the airframe and 2 of the
	# variant's module sources, NOT all of them. The module list also needs
	# `ordnance_equipment` + `ammo_apit` (common/technologies/air_techs.txt),
	# `SOV_cannon_20mm_shvak_2x_nose_prop` (air_techs_sov.txt) and
	# `armour_light_seat` / `self_sealing_fuel_tanks`, none of which is checked
	# here. On a historical research order SOV holds all of them long before the
	# La-5FN, so this is not a live gap - but on an ahistorical order the effect
	# can drop a module, the result stops matching fighter_mr_7_lr's
	# `target_variant`, and `fire_only_once` means there is NO retry. That risk
	# is strictly lower than Fix 70's (which checked one tech), so it is not a
	# regression; do not read this comment as a completeness claim. Widening the
	# trigger to the full module set is the follow-up if R31's anachronism leg
	# ever passes while the design leg still finds nothing.
	#   sov_fighter_multirole_ad_tech_7 -> the SOV_la_5fn_airframe itself, plus
	#       SOV_engine_shvetsov_m_82fn_1x and armoured_glass_light.
	#   sov_fighter_ad_tech_1           -> fuel_tanks_small/medium/large (the I-15
	#       tech, start_year 1936). Redundant in practice - SOV holds it a decade
	#       before the La-5FN - but it is the same tech fighter_mr_7_lr's own
	#       `enable` waits on, so stating it keeps the two gates in step and makes
	#       the fallback deterministic rather than a silent module drop.
	trigger = {
		tag = SOV
		is_ai = yes
		has_tech = sov_fighter_multirole_ad_tech_7
		has_tech = sov_fighter_ad_tech_1
	}

	immediate = {
		create_equipment_variant = {
			name = "Lavochkin La-5FN (long range)"
			type = SOV_la_5fn_airframe
